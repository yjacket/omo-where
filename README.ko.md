# omo-where

[English](README.md) | 한국어

OMO/Senpi TUI 확장입니다. `/where`를 치면 하네스가 프롬프트 조각, 스킬, 확장, 규칙, 템플릿, 테마, MCP 서버, 훅, 메모리, 설정을 찾아본 모든 자리가 오버레이로 뜹니다. 줄마다 들어왔는지, 없는지, 밀렸는지, 꺼졌는지, 깨졌는지와 함께 지금 세션이 디스크와 맞는지도 보여 줍니다.

## 보이는 것

왼쪽 칸은 범주이고, 손볼 줄이 있을 때만 숫자가 붙습니다. 오른쪽 칸 맨 위의 굵은 줄은 그 범주가 무엇인지, 흐린 줄은 판단 기준입니다. 그 아래로 하네스 우선순위대로 후보가 늘어섭니다. 하네스가 뒤진 폴더는 번호 없는 줄이고, 그 안에서 찾은 것이 이름으로 뒤따르며, 묶음 앞뒤에는 빈 줄이 들어갑니다. 번호는 항목에만 붙습니다. 쓰이는 줄은 이름만 나오고, 나머지 줄은 이름 뒤에 아래 표의 상태가 붙습니다. `폴더 없음`처럼 이유가 상태를 말하면 이유만 나옵니다. 구분선 아래 줄은 고른 줄의 전체 경로와 이유입니다. 80칸에서 실제로 캡처한 화면입니다(스킬, 가운데 줄 생략).

```
where · 문제 4개 · 사용 136 · 없음 38 · 밀림 3 · 꺼짐 20

 시스템 프롬프트      │ 모델이 필요할 때 읽는 SKILL.md · 이름과 설명만 시스템 …
 지침 파일            │ 같은 이름이면 먼저 찾은 쪽이 이김
 스킬               1 │
 확장               3 │ ./.omo/skills  폴더 없음
 규칙                 │ ./.agents/skills  폴더 없음
 프롬프트 템플릿      │ ./.pi/skills  폴더 없음
 테마                 │
 MCP                  │ ~/.omo/agent/skills  전역
 훅                   │    1. orca-cli
 메모리               │    2. omomeow
 설정                 │
                      │ ~/.agents/skills  전역
                      │    3. visual-board
                      │    4. orchestration
                      │    5. orca-cli  링크 · 같은 파일(링크)로 이미 들어옴
                      │    6. find-skills
                      │    7. dori-mode
────────────────────────────────────────────────────────────────────────────────
./.omo/skills · 폴더 없음
Enter 열기 · w 이긴 쪽 · e 편집 · f 문제만 · r 다시 읽기 · q 닫기
```

Enter를 누르면 읽기 전용 보기 화면이 열립니다. 아래 줄은 `↑↓ PgUp/PgDn 스크롤 · e 편집 · Esc 뒤로`입니다.

## 설치

클론한 폴더에서:

```powershell
.\install.ps1
```

```sh
sh install.sh
```

그다음 실행 중인 세션에서 `/reload`를 칩니다. 스크립트는 `extension/omo-where/`를 `<agentDir>/extensions/omo-where`로 복사합니다. agentDir은 `OMO_CODING_AGENT_DIR`, `SENPI_CODING_AGENT_DIR`, `PI_CODING_AGENT_DIR` 중 처음 설정된 값이고, 없으면 `~/.omo/agent`입니다. 먼저 `omo-where.tmp-<pid>` 폴더에 복사하고, 옛 사본을 지운 뒤 이름을 바꾸므로 핫 리로드가 반쯤 복사된 폴더를 보지 않습니다. 아무것도 내려받지 않습니다.

## 키

목록 화면 아래 줄:

```
↑↓ 이동 · ←→ 칸 · Enter 열기 · w 이긴 쪽 · e 편집 · f 문제만 · r 다시 읽기 · q 닫기
```

보기 화면 아래 줄:

```
↑↓ PgUp/PgDn 스크롤 · e 편집 · Esc 뒤로
```

`j`/`k`는 ↓/↑와 같습니다. 범주에서 Enter를 누르면 그 범주의 줄로 갑니다. Esc나 `q`는 오버레이를 닫고, 보기 화면의 Esc는 목록으로 돌아갑니다. `w`는 밀린 줄을 이긴 줄로 갑니다. `f`는 손볼 줄만 남깁니다. `r`은 디스크를 다시 읽습니다. 보기 화면에서 Home/End는 처음과 끝으로 갑니다. 좁은 터미널에서는 아래 줄이 화살표 안내부터 빼서 `q 닫기`가 늘 보입니다.

## 범주와 상태

범주는 이 순서로 나옵니다.

| 범주 | 뜻 |
|---|---|
| 시스템 프롬프트 | 모델이 이번 세션에 받은 프롬프트 전체와 그 조각 · 지침 파일과 스킬 목록도 여기 합쳐짐 |
| 지침 파일 | AGENTS.md·CLAUDE.md · 폴더마다 하나씩 시스템 프롬프트에 그대로 붙음 |
| 스킬 | 모델이 필요할 때 읽는 SKILL.md · 이름과 설명만 시스템 프롬프트에 들어감 |
| 확장 | 명령·도구·화면을 더하는 코드 · 세션 시작 때 불러옴 |
| 규칙 | 작업 중에 조건이 맞으면 더 붙는 지침 파일 |
| 프롬프트 템플릿 | /이름으로 불러 쓰는 프롬프트 파일 |
| 테마 | TUI 색 테마 파일 |
| MCP | 모델이 도구로 쓰는 MCP 서버 설정 |
| 훅 | 정해진 때 자동으로 도는 명령(hooks.json) |
| 메모리 | 세션이 끝나도 남는 메모리 파일 |
| 설정 | 하네스 설정 파일과 지금 세션의 설정값 |

| 상태 | 라벨 | 뜻 |
|---|---|---|
| loaded | 사용 | 하네스가 찾아서 씀 |
| missing | 없음 | 찾아봤지만 없음 |
| shadowed | 밀림 | 있지만 우선순위가 더 높은 쪽이 이김 |
| shadowed (링크) | 링크 | 같은 파일을 링크로 한 번 더 찾음. 설계대로라 문제로 세지 않음 |
| disabled | 꺼짐 | 있지만 읽지 않음: 설정에서 끔, 신뢰하지 않은 프로젝트, omo가 읽지 않는 폴더(Claude Code, `~/.pi`, `~/.senpi`), 확장 진입 파일이 아님 |
| error | 오류 | 있지만 읽기나 해석에 실패 |

| 라이브 표시 | 라벨 | 문제 문구 |
|---|---|---|
| session-only | 세션에만 | 세션에는 있지만 지금 디스크에 없음 - 지운 뒤 /reload 안 함? |
| disk-only | 디스크에만 | 세션 시작 뒤 생김 - /reload 해야 들어옴 |
| changed | 바뀜 | 세션 시작 뒤 내용이 바뀜 - /reload 해야 적용 |

## 파일이 바뀔 때

스킬, 확장, 지침 파일을 더하거나 지우면 omo가 잠시 뒤 스스로 다시 불러오고, 그때 오버레이가 닫힙니다. `/where`를 다시 열면 바뀐 상태가 보입니다. 다시 불러오기 전까지는 세션이 아직 들고 있는 줄에 `세션에만`, 새 파일에 `디스크에만`이 붙습니다.

## 판단 방식

omo-where는 먼저 하네스에 묻습니다. 호스트 함수(패키지 해석, 스킬 읽기, 지침 파일 읽기, 프런트매터 해석)를 직접 부르고, 그 답을 지금 세션과 비교합니다: 들어온 지침 파일, 스킬, 확장 경로, 시스템 프롬프트, MCP 서버, 훅 출처. 부를 함수가 없는 곳은 하네스 검색 순서를 옮긴 후보 표를 따라갑니다. 규칙과 MCP의 밀림 판단은 하네스 로직을 따라 만든 것이라 업데이트 뒤 어긋날 수 있습니다.

## 안전

- 파일에 쓰지 않고 리로드도 일으키지 않습니다.
- 설정은 읽기 전용 저장소로 읽습니다. 설정 파일을 다시 쓸 수 있는 `SettingsManager.create`는 부르지 않습니다.
- 패키지 해석은 없는 패키지를 늘 건너뜁니다. 아무것도 설치하지 않습니다.
- 편집은 외부 편집기로만 합니다. 에이전트가 일하는 동안은 거절하고(`에이전트가 일하는 중에는 편집 안 함`), 업데이트가 덮어쓰는 runtime이나 omo-ai 파일도 거절합니다(`업데이트 때 덮어써지는 파일이라 편집 안 함`). 가상 줄은 `파일만 열 수 있음`이 뜹니다.
- JSON 보기와 설정 줄의 비밀 값은 `<가림>`으로 보입니다.

## 한계

Windows 11, Bun 1.4.2에서 @code-yeongyu/senpi 2026.10.10, omo-ai 5.1.19로 시험했습니다. 하네스 내부를 읽으므로 업데이트가 보이는 내용을 바꿀 수 있습니다. 내부 기능이 없으면 멈추지 않고 안내를 띄운 뒤 지금 세션과 폴더 확인만으로 보여 줍니다.

시스템 프롬프트 범주는 세션의 기본 프롬프트를 보여 줍니다. omo가 턴마다 덧붙이는 내용(메모리, 규칙 안내)은 빠질 수 있어서, 메모리 범주는 세션의 스킬 경로나 폴더 이름으로 메모리 폴더를 찾습니다.

## 개발

```sh
bun test
```

테스트에는 설치된 하네스 함수를 시험 폴더에 돌려 줄과 맞춰 보는 parity 테스트가 들어 있습니다. Bun 1.4 이상이 필요하고, 빌드 단계와 npm 의존성은 없습니다.

`qa/tui-qa.mjs`는 이 확장과 `qa/dump-ctx.ts`를 붙여 omo를 가상 터미널에서 띄우고, JSON 단계 목록을 따라 움직인 뒤 헤드리스 Chrome의 xterm.js로 `.png`, `.ansi`, `.txt`를 저장합니다.

```sh
bun qa/tui-qa.mjs --cwd <dir> --cols 150 --rows 45 --steps qa/steps/smoke.json --out .omo/evidence/smoke
```

단계: `wait`, `waitNew`(마지막 키 입력 뒤 출력만), `idle`, `send`, `shot`, `mark`, `rm`. 슬래시 명령은 입력한 뒤 자동완성 줄을 `waitNew`로 기다렸다가 Enter를 보냅니다. 너무 이른 Enter는 에이전트에게 프롬프트로 갈 수 있습니다.
